03

字库面板详解 —— 这个案例说清楚"卡帕西知识库"是什么

字库面板不是一个通用的"文件管理器"，它展示的是一套特定结构的数据：材料科学文献被拆解成"点"（材料）和"边"（材料之间的关系），每条边都能追溯到具体论文。这套结构现在已经在跑，V1 只需要把这份真实数据读出来、按下面这个样子摆出来，不用设计新的信息架构。

点开一条边，应该看到什么

材料 ALaFeAsO
材料 BLaFeAsO1-xFx
关系类型R4 · 氧位F掺杂
文献 DOI10.1103/PhysRevB.78.020512
年份2008
证据强度direct
证据摘录"The F doped LaFeAsO, a recently discovered superconductor with the high Tc of 26 K"

这条数据是真实存在的，来自项目仓库的 knowledge/edges.csv 第一行。字库面板点开任意一条边，都应该长这样——不是占位假数据，是把这个文件真实读出来渲染。

核心 vs 扩展——两种数据不能视觉混淆

系统里有两批数据，可信度不一样，UI 上必须能一眼分清：

核心数据每条边都有真实 DOI，人工核验过，91个点 / 79条边
扩展数据来自公开知识图谱批量导入，没有逐条核验，46个点 / 210条边，仅用于辅助参考

V1 做法很简单：两种数据加一个小标签区分（比如上面示意图里的"核心/扩展"标签），不用做复杂的可视化，能让人一眼看出"这条数据能不能直接信"就够了。

04

接口契约 —— 四个端口

后端按这四个文件跟前端对接，字段名和层级现在已经定了，谭直接按这个格式读文件渲染，不需要理解后端具体怎么算出来的。

1 · 记忆 —— 字库数据从哪读

// knowledge/edges.csv 每行一条边 { "材料A": "LaFeAsO", "材料B": "LaFeAsO1-xFx", "关系类型": "R4", "文献DOI": "10.1103/PhysRevB.78.020512", "年份": 2008, "证据强度": "direct", "证据说明": "..." }
对应上面第03节展示的那条边。扩展数据在 knowledge/edges_matkg.csv，字段名不同，前端按同一个视觉规则打标签即可，不用理解字段差异的原因。

2 · 技能 —— 概览数字从哪读

// outputs/pipeline_report.json { "L2_structure": { "core_materials_count": 91, "core_edges_count": 79, "extended_nodes_count": 46, "extended_edges_count": 210 }, "L4_application": { "candidates_generated": 6 } }
字库面板右侧那几个统计数字（示意图里的91/46/79/210/6），直接读这个文件的对应字段，不用自己算。

3 · 灵魂 —— 身份定义

静态文件，定义这个 Agent 是谁、语气风格、边界。V1 阶段前端不需要解析内容，只要有这个文件存在、能被工作流读取即可，具体内容后续再补。

4 · 工作流 —— 对话怎么触发后端

V1 阶段对话区可以先做成界面样式（输入框+气泡），不用真的接通后端执行——等后端这边把执行逻辑理清楚了再对接，这次先把壳做扎实。

验收标准

  • 三栏布局能在本地打开，导航栏三个按钮能切换（不要求功能，要求能点、有视觉反馈）
  • 字库面板读取 edges.csv 真实数据，展示出至少几条真实边（不是硬编码假数据）
  • 核心数据和扩展数据视觉上能区分（一个小标签即可，不需要复杂设计）
  • 点开任意一条边，能看到第03节展示的那七个字段
  • 整体安装包/运行方式简单，能打开就算过关，不追求长期无 bug
