# 材料文献 Agent 执行铁律

本目录是 agent/前端调用运算层的端口，不另起一套算法。意图名称、入参、函数和产物以同目录 `workflow.json` 为机器可读契约；它与 `frontend_dev_spec.md` 第 04 节描述的是同一接口层。

## 不可越过的边界

1. `raw/` 是只读原料层。不得改写、补写或删除原文；新检索结果只能由检索流程新增。
2. 不修改 `knowledge/edges.csv` 现有 schema。新增核心边必须有真实 DOI 和可从原文核对的证据摘录；没有摘录就不入库。
3. 核心 DOI 边与 MatKG 聚合弱边必须隔离。L3/L4 类比源只使用 `load_core_edges()`；MatKG 只可作为向量空间背景，不能包装成强证据。
4. 所有推断产物必须标为 `候选假设(未验证)`，并保留数据库或实验交叉验证的下一步，不能写成已证实结论。
5. 搜索数值信号来自 `rules.cosine`，不是后验分布或 Expected Improvement。对外方法名使用“可解释余弦评分 + LLM引导扩张与剪枝”，不得称为贝叶斯优化。
6. LLM 决策按 STEP→Gemini→启发式兜底执行。每个逻辑调用必须写入 `outputs/llm_calls/`；只有成功解析真实 provider 响应时才能写 `real_llm_api_called=true`。
7. 密钥只在运行时从环境或仓库外 env 文件读取，绝不写入日志、审计、产物或 Git。
8. 搜索必须保持已观察候选 ID 不重复；轮次扩张必须能开放首轮不存在的新证据方向。数据不足时如实结束，不为凑数量放宽证据标准。
9. 只调用 `workflow.json` 白名单内的公共函数。不得从此端口改前端 UI、改 schema、改 raw 层或直接写未经验证的知识边。

## 调用约定

- 工作目录为仓库根目录，并将 `src/` 加入 Python import path。
- 结构化输出优先读取函数返回值；长任务的落盘产物以 `workflow.json` 的 `artifacts` 字段为准。
- 错误必须向调用方返回真实异常或显式降级信息，不能吞掉失败后伪造成功结果。
- 搜索默认家族只允许 `122`、`1111`、`11`、`MgB2`；其中 `MgB2` 映射到内部结构标签 `diboride`。

## 交付前检查

运行搜索/验证后确认：JSON 可解析、候选 ID 唯一、证据层级未混用、后续轮存在首轮外新 ID、LLM 调用数与审计文件一致、`real_llm_api_called` 与实际 provider 状态一致。
