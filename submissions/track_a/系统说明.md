# 材料证据链：Track A 系统说明（初稿）

## 1. 系统边界

本系统面向超导材料文献中的构效关系发现，完成“检索—抽取—关系编码—类比迁移—候选审计—证据链报告”的最小闭环。系统不宣称全自研：算法增量、证据分级与审计机制由团队实现，检索、基础模型、外部数据和桌面端框架均按来源明确披露。当前 6 条输出是**待验证候选假设**，不是已确认的新材料或 Research Gap；本机未配置 Materials Project API key，因此本稿只给出交叉验证方案。

## 2. 自研核心

### 2.1 L1—L4 分层算法

| 层级 | 自研实现 | 输入→处理→输出 | 可核验产物 |
|---|---|---|---|
| L1 文献事实 | `src/graph.py` | DOI 证据边→材料成分解析与向量化→可计算图节点、边 | `knowledge/edges.csv` |
| L2 关系结构 | `src/rules.py` | 同类关系向量→余弦比较与编码退化检测→非退化平行证据 | `outputs/pipeline_report.json` 的 `L3_rules` |
| L3 类比规则 | `src/application.py` | 已有非退化变换→向目标材料迁移→候选组成变化 | `L4_application.candidates` |
| L4 搜索应用 | `src/search.py` | 候选池与轮次历史→筛选及扩张决策→跨轮候选与停止原因 | `outputs/search_runs/*.json`、`pool_growth_by_round` |

搜索的结构性增量是“每轮扩张”：候选不再只在循环前一次性生成，而是根据本轮扩张决策继续暴露次优、次次优源变换。四个家族记录均保留首轮候选数、最终候选数、轮次来源和停止原因，候选池增长可以直接审计。

### 2.2 证据分级和物理隔离

- 核心集 `knowledge/edges.csv`：81 条逐行 DOI 可溯源边，53 个唯一 DOI，94 个核心材料；字段包含材料 A/B、R1—R9 关系类型、DOI、证据强度和证据摘录。
- 扩展集 `knowledge/edges_matkg.csv`：210 条 MatKG 弱证据边，无逐行 DOI，只用于扩大成分向量空间，不参与强证据结论。
- `load_core_edges()` 与 `build_graph(include_extended=...)` 要求调用方显式选择是否加载扩展集，避免弱证据静默混入核心层。

### 2.3 审计式 LLM 接入

`src/llm_client.py` 在两个决策点接入 LLM：候选排序和下一轮扩张判断。每次逻辑调用无论成功、失败还是降级，均写入 `outputs/llm_calls/`，记录任务、输入摘要、模型、调用模式和 `real_llm_api_called`，不写入密钥。调用链为 STEP→Gemini→可解释启发式；外部服务不可用时，系统明确标记 `heuristic_fallback_llm_unreachable`，不把规则结果伪装成模型结果。

累计审计底账含 160 次逻辑决策，其中一轮联网运行有 39 次 `gemini-3.6-flash` 成功调用；其余为如实标注的降级记录。为完成投稿隐私检查，本轮还把审计中的本机密钥文件绝对路径改为仅保留文件名，不改变模型响应和成功状态。该数字描述调用底账，不等同于 39 个科学发现。

### 2.4 Agent 四端口

`agent/memory.json`、`agent/skill.json`、`agent/soul.json`、`agent/workflow.json` 分别约定事实记忆、工具能力、证据纪律和执行工作流。`soul` 要求事实/推论/假设三层分开，`workflow` 规定检索、构图、搜索、验证和报告的输入输出契约。

## 3. 外部组件与复现影响

| 外部组件 | 用途 | 来源/许可 | 边界与复现影响 |
|---|---|---|---|
| MatKG | 扩大材料关系向量空间 | Venugopal & Olivetti（2024），CC0 | 仅 210 条弱证据边；不作强结论 |
| Sciverse API | 文献检索与候选筛选 | 赛事官方推荐检索源 | 需运行时凭据；调用结果和查询参数留痕 |
| Gemini API | 两个审计决策点的真实模型调用 | Google 商业 API，模型 `gemini-3.6-flash` | 无 key 时降级；成功与否逐条标记 |
| React/Electron/Vite 桌面端 | 展示知识图谱和交互工作台 | `LL-LK/cl-agent`，谭力奎开发 | 前端并非本仓库算法自研成果；通过约定数据接口接入 |
| matplotlib | 结果图生成 | Python 可视化库 | 仅影响可视化，不参与候选判定 |

## 4. 当前能力与限制

已完成：81 条核心边构图、326 组非退化证据、6 条待验证候选、四家族搜索验收 PASS、17/17 自动化测试、完整调用审计。未完成：Materials Project/OQMD/NOMAD 的候选新颖性交叉验证、计算模拟和实验验证。因此，本系统当前达到“可复现地产生和排序候选假设”的程度，尚不能把任何候选宣称为已发现的新材料。
