## 3. 强项

1. **证据等级不混用。** 3.1与3.3明确81条核心边和210条MatKG弱边物理隔离，弱边不作强结论。
2. **LLM真实在回路且可降级。** 3.1、4.2披露两个决策点、160次逻辑决策、39次真实Gemini成功和其余降级；没有把调用成功等同于科学发现。
3. **不是普通RAG。** 3.2第8—12步形成组成向量→非退化关系→类比候选→跨轮扩张的可计算链。
4. **负面状态诚实。** 1.3、4.1、4.2均写明没有MP key、未执行交叉验证、不得称真Gap。
5. **复现与隐私边界清楚。** 5.1—5.3披露私有仓库、raw/knowledge/src结构、第三方数据不转存、密钥不入库和日志脱敏。

## 4. 弱项（按严重度）

1. **科学验证未闭环。** 4.1仍是MP/OQMD/NOMAD执行方案，6条候选没有数据库命中/未命中结果，也没有领域签审或实验数据。
2. **领域覆盖仍小。** 2.1的81条核心边是工程证据底账，不是超导领域文献体量；对候选新颖性与泛化能力的支撑有限。
3. **可操作组成式需要人工规范化。** 含 x、加号、混相或添加剂的候选不能直接等价为Materials Project精确组成查询。
4. **团队提交信息未销账。** 6.2领域签审人、6.3作品公开链接和附录中的成本/镜像版本仍待补。
5. **版式视觉检查受环境限制。** 已完成模板标题、节结构、样式、字数和占位符审计，但当前Windows环境缺少LibreOffice且Word类型库异常，未取得逐页渲染图。

## 5. 改进建议

1. 配置 MP_API_KEY 后执行6条候选交叉验证，并将请求组成、匹配阈值、材料ID和原始响应摘要写入 outputs/mp_crosscheck.json；随后补OQMD/NOMAD和文献排重。
2. 扩充核心边时按结构家族设最小覆盖目标，新增边必须保留DOI和证据摘录，并报告新增前后的规则稳定性。
3. 为变量组成式增加“可自动解析/需人工归一化/多相不可直接查询”三级状态，避免错误生成精确分子式。
4. 提交前由团队补齐领域签审人、作品链接、API成本和Docker镜像版本；未确认信息保持【待补充】，不得猜写。
5. 在装有可用Word或LibreOffice的机器上导出PDF，逐页检查表格跨页、标题孤行、页脚和中文换行后再定稿。
